# FC 路线阶段 A：执行流水线优化与实机验证

日期：2026-10-31（Asia/Shanghai）。仓库 HEAD：`64c009d`。对象为当前 FC INT8 实现 `16→29→16→16→4`，对应已有三输入网络的硬件补零布局；本轮没有重新编译 ONNX、修改网络、权重、有效通道、量化精度或运算参数。

**本轮已验证最快版本为 A4，端到端平均 77.455900 μs，相对 Baseline 147.213140 μs 减少 47.39%，加速 1.901×。** 五个版本均完成三轮独立编译、烧录和 1000 次正式样本，共 15000 次；另有五个独立详细计时批次，共 5000 次。每个版本另完成 570 个输入的逐层实机原始数据检查，五版完全一致。

## 2. 固定条件和原始执行流程

硬件为 LAUNCHXL-F28P55X / XDS110，CPU1；SYSCLK 与计时器均配置为 150 MHz。每轮 Vin=90 V、预热 10 次、正式 1000 次，关闭 detail-profile；重新编译全部应用对象及 FC 运行代码并重新烧录。每批连续运行后再暂停读数，测量批次中不插入调试暂停。

每轮检查待机状态、无启动请求、无故障、无超时、有效输出 `[0.453125, 0.25, 0, 1]`，并读回 EPWM7、EPWM4、EPWM5、EPWM10 的 OST 均锁定。四层 FC 使用 **5 次 NPU 启动及中断**，因为第一层 16→29 原本分为两个子层；所有版本每次推理的层中断分布保持 `[0,2,1,1,1]`，1000 次推理合计 5000 次中断。

原始输入在应用层生成 16 路 float32：`[-0.5, Vin/140, 0.285714, 0, …]`。CPU 量化、pack 后提交第一层；三个隐藏边界均为：

```text
NPU packed 输出 → CPU unpack（无符号）→ /256 → ReLU → ×256
→ floor(+0.5) → clip[0,255] → CPU pack → 下一层 NPU
```

最后一层保持 signed unpack 和 `×1/64` 输出恢复。当前基线已经包含 RAM 中执行、RAM 常量及指令表复用，本轮保持这些设置，不将它们重新计为阶段 A 收益。

原始主要 CPU 开销来自隐藏层浮点转换、16 路输入量化、层间 pack/unpack，以及每子层的参数和配置装载。下面第 6 节提供本次独立详细计时结果。

## 3. 三项优化及严格等价依据

### A1：隐藏层恒等转换和复制消除

对全部合法隐藏码 `u∈{0,…,255}`，原表达式为：

```text
clip_uint8(floor(max(float32(u) × 2^-8, 0) × 2^8 + 0.5))
```

`u` 转 float32 精确；乘以 2 的整数幂仅改变指数，范围内无上溢、下溢或有效位损失；无符号输入保证 ReLU 不改值。恢复到 `u` 后，加 0.5 得到可精确表示的半整数，floor 恢复 `u`，上下限也不改值。因此整个转换对所有合法输入逐位恒等，不依赖 scale 近似互逆。

补丁按完整表达式、类型、上下限和取整规则匹配，不只检查两个 scale 字符串。三个转换调用被删除，后续 pack 直接读取 unpack 缓冲区；没有新增 identity copy。case 1 和 case 3 的 pack 在原缓冲区向前压缩，写位置 `floor(i/2)` 不会覆盖后续待读位置。

INT4 不满足此证明：三个隐藏层的 scale 乘积约为 1.005264、1.009266、0.996312。穷举分别发现 160、201、120 个不恒等码，例如 95→96、54→55、136→135；INT4 消除被拒绝，详见 [INT4 排除证据](results/int4_exclusion.json)。

### A2：层间 packed 零拷贝

相邻 FC 的隐藏结果和输入采用相同低字节优先 packed 格式。由于隐藏转换已经严格证明恒等，层间可以直接让下一层读取上一层输出；A2 从基线独立应用，并以恒等证明作为合法性条件，因此 A1 与 A2 的收益不能相加。

C28 的 TVM `int8_t/uint8_t` 实际分别映射为 `int16_t/uint16_t`。unpacked 一个通道占一个 16 位存储单元；packed 一个 16 位单元存两个 8 位通道，SDK 的 `__byte` 决定低字节优先。本补丁以 C28 存储单元为偏移，不使用桌面机的 byte 偏移推算目标地址。

| FC 层 | 基线输入偏移 | 基线输出偏移 | A2/A4 输入偏移 | A2/A4 输出偏移 | 有效输入 / 输出通道 |
|---|---:|---:|---:|---:|---|
| 0 | 0 | 32 | 0（A4 为独立 GS 输入） | 32 | 16 / 29 |
| 1 | 0 | 32 | 32 | 0 | 29 / 16 |
| 2 | 32 | 16 | 0 | 32 | 16 / 16 |
| 3 | 0 | 16 | 32 | 16 | 16 / 4 |

偏移均相对 `global_workspace_0_var`，单位为 16 位存储单元。所有 NPU 输入、输出保持对齐且互不重叠；最后输出仍在偏移 16，再 unpack 到偏移 0，避免原地扩展破坏待读数据。

29 通道占 15 个 packed 单元，最后有效通道位于低字节。A2/A4 在第一隐藏边界仅执行 `workspace[46] &= 0x00ff`，明确清零高填充字节，匹配原 unpack 零扩展后 pack 的结果；其他层不需要填充写入。NPU 的有效长度、权重、指令、MMR 模板及子层定义保持原样，只调整调用时的数据地址；没有更改中断调度。

### A3：应用层整数预量化

不使用 NNC `skip_normalize`。应用层仅对 Vin 通道执行原固件同顺序公式：

```c
float normalized = vin_volts / 140.0f;
float q = floorf(normalized * 64.0f + 0.5f);
q = min(q, 127.0f);
q = max(q, -128.0f);
```

scale、zero-point=0、floor、clip 和 float32 运算顺序均沿用原式。常量 `-0.5f` 的码为 -32，`0.285714f` 的码为 18，补零的零码为 0。初始化时预存 `0x00e0,0x0012,0,…`，每次只更新第一单元的 Vin 高字节；`DAB_NN_init()` 也显式恢复常量，避免初始化清零使常量丢失。

输入 ABI 明确改为 **8 个 uint16_t packed 单元**；生成入口读取该整数缓冲区，删除原输入量化及输入 pack 调用。没有将整数缓冲区伪装为仍需 float 量化的原接口。输出 ABI 保持 float32[4]。

实机确认整数输入必须放在已验证的 GS RAM 路径，并保持 16 单元对齐。初次 LS5 输入实验中 CPU 读回 `0x29e0,0x0012,0,…` 正确，但 NPU 输出不一致；该轮已拒绝。仅将缓冲区移到 `ramgs1` 后通过全部输出及逐层检查，正式成绩使用修正后的版本；这也说明主机量化证明不能替代目标内存路径检查。

## 4. 主机验证

- 实际生成的 CPU 函数及 IRQ 执行图在主机编译运行，以显式 16 位存储和 SDK `__byte` 等价操作重现 C28 pack/unpack；禁用浮点乘加收缩。两种隐藏转换函数分别穷举 256 个码，检查结果和尾部保护区。
- 长度 1～65 分别覆盖全部 65536 种双字节组合，验证不重叠 pack、原地向前 pack、奇数通道填充、脏高字节、保护区和不应修改的存储单元；单独包含长度 29。
- 501 个 Vin 工作点，加全部输入码量化边界的相邻 float32 值及限幅外探测，共 1283 个输入；每点 8 组不同确定性 NPU 输出。应用层初始化与预量化函数也参与编译验证。
- 比较五个版本每层的输入码、输出码及最终 float 位模式，输出文件 SHA-256 全部相同；对错误 clip、错误取整和 INT4 scale 的补丁必须拒绝。
- NPU 主机替身仅用于检查执行图和数据传递，不模拟 NPU 算术或速度。实际 NPU 核函数、参数与配置源码 `lib2.c` 和正式驱动源码与基线逐字节相同，结合每层输入相同，可对未改动的 NPU 计算逐层归纳；实机又做了下节逐层原始数据核对。

可复核文件：[主机验证](results/host_verification.json)、[补丁脚本](patch_stage_a.py)、[验证程序](verify_host.py)。

## 5. 逐层实机一致性

验证使用独立的 capture 固件，不计入性能统计。每版测量 501 个工作点，加 23 个量化跳变点及其 float32 前驱、原值、后继，共 **570 点**；分三批，每批 190 点。

每点保存 8 个 packed 输入单元、四层共 33 个 packed 输出单元和最终四个 float 的原始 16 位存储单元。逐元素比较全部五个版本，**输入、四层整数结果和最终浮点位模式完全相同**；仅屏蔽第一层最后单元中不属于有效通道的高填充字节。没有用浮点容差代替位比较。

每批另核对完成数、无超时、待机、无启动/故障、四路 OST 和 RAM 常量副本。见 [实机正确性验收](results/board_correctness.json) 及 [570 点原始记录](results/capture/Baseline.json)、[A1](results/capture/A1.json)、[A2](results/capture/A2.json)、[A3](results/capture/A3.json)、[A4](results/capture/A4.json)；相邻同目录 `版本_批次.json` 包含调试原始读数。

## 7. 独立收益与组合关系

A1 独立消除三次浮点恒等处理及中间复制；A2 独立从原始基线删除整个隐藏 unpack→恒等处理→pack，并使用直接地址连接，因此包含 A1 消除的同一批工作。A3 独立移走输入 float 量化循环与首次 pack，保留 Vin 原公式且常量预计算。

A4 同时采用全部合法消除。与 A2 相比增加应用层整数输入，与 A3 相比增加全部隐藏边界直连。正式收益来自版本间重新测量，不将三项独立收益相加；所有收益均基于同一 INT8 网络和固定权重。

## 8. 尚存瓶颈与性能上限

已经消除：三个隐藏层的反量化、ReLU、重新量化、floor、clip、复制，以及三次隐藏 unpack/pack；输入侧 15 个恒定特征的运行时量化和整段首次 pack 也被删除。Vin 的归一化、原 floor/clip 规则和最终输出恢复保留。

仍存在：五次子层启动与完成中断、每层运行描述和地址设置、参数装载、既有指令表切换、MMR 配置、硬件执行等待，以及应用准备和输出发布。五次中断和第一层拆分来自当前生成图及运行方式；参数每子层覆盖、指令复用检查与完整寄存器配置属于当前运行时机制，不能直接断言是不可改变的硬件下限。

本轮没有修改中断调度、MMR 差分写入、参数驻留或指令驻留策略。详细计时仍可见这些成本，但插桩会扰动时间，不能把详细分项从正式端到端值中扣除来宣称理论最低时间。

在阶段 A 范围内可继续验证的差距包括：Vin 精确量化与应用准备的调用/存储成本，剩余最终 unpack/输出恢复的合并机会，以及内存放置和编译结果对同语义代码的影响；每种新方案仍须重新通过主机逐位、570 点实机和三轮性能验证。超出范围的参数驻留、寄存器减少和调度改变只能列为后续研究。因此，**A4 是本轮经过验收的最快结果，而不是已证明达到 FC 硬件的绝对上限**。
