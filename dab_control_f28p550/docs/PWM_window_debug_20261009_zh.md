# 首次启动 PWM 写入窗口故障的调试说明

适用记录：`reason=6、state=2、adcFrame=51、pwmSequence=0`，包括启用 O2 的 CPU1_LAUNCHXL_FLASH 配置。

## 已确认和待确认事项

`reason=6` 表示进入写入时窗口有效，后续检查窗口失效；不是过流故障代码。`state=2` 保存故障前的软启动状态，`pwmSequence=0` 表示尚未确认第一组装载。`g_pwmLateCommitCount` 同时累计进入过晚的暂缓和写入过程中的越界，值为 2 不能单独确定两次发生的位置。

旧 FLASH 程序虽然启用 O2，但同时定义 DEBUG。反汇编确认 PWM 中断反复调用 FLASH 内的 `EPWM_isBaseValid`，对固定外设地址也执行运行期检查。已让该检查在本文件展开，并把窗口内的外设地址循环改为常量调用，保留地址验证和全部保护条件。新反汇编确认该检查不再作为外部函数调用；PWM 中断剩余的 FLASH 调用仅为检查失败处理函数 `__error__`。

这证明额外调用已移除，不能证明用户此次故障的完整原因或上板修复结果。若仍故障，需要以下现场数据区分进入写入时余量不足、写入耗时过长或计数状态变化。新增诊断在正常路径增加两次计数读取，其本身也有少量耗时，不能当作完全无扰动的测量。

## 第二次上板记录及入口预算修正

最新窗口记录为 `stage=3、entryCounter=823、failCounter=534、failDirection=0、entryTick=4284903288、failTick=4284902986`。Timer2 经过 302 计数，按 150 MHz 约 2.013 us；入口距原保护边界只有 223 计数，约 1.487 us。因此在到零点之前，写入已经耗尽软件允许的余量，最终装载请求前的保护生效。

原判断只要求开始时 TBCTR>600，没有另外预留完成写入的时间。现在新增 `DAB_PWM_STAGE_BUDGET_COUNTS=450`，即当前配置下预留约 3 us；开始写入要求 TBCTR>1050，中途复核仍要求 TBCTR>600。进入过晚时不写任何参数，保留待处理请求，等下一次合适机会；原有 300 us 总等待期限继续有效，长期无法写入仍会关断。

450 计数是基于这次约 302 计数记录增加余量的初始值，不是已验证的最坏耗时。1250～5000 的周期范围、控制负载、后台任务和编译配置仍须实测，尤其最短周期下能否及时获得足够窗口。此修改没有提高或取消原保护边界。

模拟外设在入口 823、参数写入和最后标志清除消耗时间的条件下，修正前复现 reason=6/stage=3；修正后入口直接暂缓、计数保持 823、无装载请求，下次充足窗口成功装载并启用。原有 stage 1/2 超限测试仍能触发关断，长时间无法写入的超时测试仍通过。

同时，给出的 `g_firstFault.tick=4294174511` 比窗口的 failTick 早约 61.81 ms，不符合同一次首次窗口故障的紧邻记录关系。尚不能确定是 CCS 显示未刷新、记录来自不同运行，还是重新初始化/恢复造成混用；应完整重启、加载匹配的 out 和调试符号，暂停后同时刷新读取。现已让成功人工清故障时，首故障记录和窗口诊断一并清零，避免恢复后保留上一轮窗口记录。

## 下一次运行

保持功率级不投入运行。选择 CPU1_LAUNCHXL_FLASH，重新 Build 并加载生成的 out，从初始化开始连续运行，不在 PWM 或控制中断内单步或暂停。故障后暂停读取 `g_firstFault`、`g_pwmLateCommitCount` 和 `g_pwmWindowDiag`；不要仅 Reset CPU 后从未知外设状态继续运行，应使程序完整执行初始化。

| g_pwmWindowDiag 字段 | 含义 |
|---|---|
| stage | 0 无越界记录；1 写完周期/比较值/相位后；2 恢复从 PWM 相位载入后；3 发出最终装载请求前 |
| entryCounter | 进入参数写入前的主 EPWM7 计数值，初始周期为 2500，下降到 600 即不允许继续 |
| failCounter | 失败检查之后再次读取的主计数值 |
| failDirection | 0 向下计数，1 向上计数；与 failCounter 是顺序读取，不是同时采样 |
| entryTick、failTick | Timer2 向下计数值，按 uint32_t 无符号计算 entryTick-failTick，150 MHz 时除以 150 得到约微秒数 |

正常初始化或成功人工清故障将诊断清零，首次越界后保留，后续故障不覆盖。失败读数在检查之后采集，有少量延迟；最终诊断完成后仍需实测最短允许 PWM 周期下的最坏写入时间。

`entryCounter` 仅略高于 600 时，应重点检查前置处理占用的时间；开始余量充足但结束越过 600 时，应检查写入段耗时。`failDirection=1` 说明在读取方向时主计数器已向上计数，需要结合经过时间判断是否跨零或受到调试暂停影响。

不要减小 600 计数保护余量或删除检查来掩盖故障。IL 原始值约 228 按当前旧板系数对应约 -33.48 A，需另行确认传感器连接、零点和换算，不能当作零电流。
