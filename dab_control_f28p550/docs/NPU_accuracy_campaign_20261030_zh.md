# F28P550 NPU 精度归因与测试体系（2026-10-30）

审阅基线 `186109a`。本轮不以绕过精度约束或开启 NPU 功率闭环为目标。`DAB_NPU_POWER_CONTROL_APPROVED` 保持为 0，功率 PWM 保持 OST 锁定。

离线网格与候选模型只写在 `tools/c2000_debug/experiments/accuracy_20261030/`，不覆盖交付用 ONNX。交付库 `model/generated/npu/mod.a` 仅因补上 ISR 计时钩子而重链 `lib1.c`，网络权重与 ONNX 未改。

## 1. 测试体系修正

### 1.1 正式固件与性能测试分离

`DAB_NN_AUTO_BENCHMARK` 默认改为 0。CCS 的 `CPU1_LAUNCHXL_FLASH` / `CPU1_LAUNCHXL_NPU_FLASH` 上电后不再自动跑 1000 次推理。

独立测试构建由 `c2000_debug.py --nn-auto-benchmark` 注入 `--define=DAB_NN_AUTO_BENCHMARK=1`（写到构建目录 `dab_nn_auto_benchmark.opt`，覆盖 CCS `GEN_OPTS__FLAG`）。`benchmark_nn.py` 始终带上该开关。普通 NN 服务和控制任务在测试构建中仍按原逻辑运行，只是上电时由测试服务接管有限样本。

`g_debugBuildId` 更新为 `0x20261030`。

### 1.2 冻结的 benchmark 输出快照

新增 `g_nnBenchmarkOutput[4]` 与 `g_nnBenchmarkOutputValid`。每个正式样本在 `finishProfile` 里从本次推理的 `s_output` 拷贝；测试结束后冻结。后台 `DAB_NN_service` 仍可覆盖 `g_nnLastOutput`，不再污染对照。

实机验证（Vin=90 V，功率关闭）：

| 后端 | 冻结快照 | 测试结束后的 `g_nnLastOutput` |
|---|---|---|
| FPU | `[0.44998613, 0.24999291, -2.65e-6, 0.99999666]` | `[0.17683, 0.10934, 0.03935, 0.57924]`（偏置，Vin≈0 的后台推理） |
| NPU | `[0.4375, 0.25, 0, 1]` | 同快照（NPU 拒绝 Vin&lt;90，后台未覆盖） |

FPU 冻结快照与 `dab_nn.c` 教师网络在 90 V 的离线结果一致。此前把现场 `g_nnLastOutput` 当作 Vin=90 输出是错的。

### 1.3 NPU ISR CPU 占用

`tvmgen_default_IRQHandler` 在进入时锁存 `tinie_curr_layer`，退出时累计 CPU 时间。首层 `TINIE_setup` 仍在前台 `npuSubmit` 内，不记入 ISR。

区分：

| 量 | 含义 |
|---|---|
| `prepare + npuSubmit + publish` | 前台 CPU |
| `npuIsr` | 四次完成 ISR 的 CPU 累计，不含 `TINIE_start` 之后的硬件等待 |
| `npuCompletion - npuSubmit - npuIsr` | 近似 NPU 硬件计算 + 中断开销缝隙 |
| 详细分段 PARAMS/INS/REGS | ISR 内部子集；正式成绩关闭 `--detail-profile`，避免与 `npuIsr` 相加 |

实机（1000 次正式样本 × 3 轮，结果三次相同）：ISR 4 次/推理，层计数 `[0,1,1,1,1]`，合计 4000 次；单次最大 1492 tick = 9.947 μs；每次推理 ISR 累计 23.061 μs；平均单次 ISR 5.765 μs。

ISR 计时本身给端到端增加约 6.4 μs（相对上一轮未插桩的 56.43 μs）。下面正式成绩带插桩，不能与上一轮未插桩数字直接当“变慢了 6 μs 的算法回归”。

## 3. 量化误差归因

教师：`dab_nn.c` 原始 FPU。紧凑浮点 `4→32→12→8→4` 在 90～140 V、步长 0.1 V 上最大绝对误差约 1e-6，PWM 计数误差 0 或 1（整数截断边界），结构等价。

交付 INT8（`dab_npu_narrow_ptq.onnx`）相对教师：

| 输出 | 最大绝对误差 | 官方网格 PWM 最坏计数 |
|---|---:|---:|
| D1 | 0.04887 | 与 T 一起映射后见下 |
| D0 | 0.03709 | |
| D2 | 0.02695 | |
| T | 0.04887 | |

PWM 按固件真实映射计算：`ramp=1`、`duty=0`，`tbprd=(uint32_t)(T_gain*2500)`，比较值为 `(uint16_t)(归一化相移*period)`，向零截断。

- 官方网格 90～140 V / 0.1 V：**最大 122 个 PWM 计数**，平均 36.3 个。最坏点 **Vin=134.7 V**（T 误差 0.04887 → 周期 122 计数）。
- 不满足“四个输出均不超过 1 个实际 PWM 计数”。
- 92.2～92.5 V 整段 INT8 输出非法（相对 T 越界）；加密到 0.01 V 后 92.20～92.50 共 31 点全部非法。
- 20～140 V 外推不计入验收：最坏 781 计数，另有 69.5 V 一带非法。

Vin=90 V 同工况：FPU 快照 D1≈0.450，NPU D1=0.4375，仅这一项已经是 31 个比较计数。

### 3.1 误差源分解

逐项替换（紧凑浮点上按 TINPU 的 `floor(x/scale+0.5)` 插入量化）：

| 消融 | 最大 PWM 计数 | 含义 |
|---|---:|---|
| 紧凑浮点 | 1 | 结构不是问题 |
| 只量化最终输出 1/64 | **20** | 统一输出网格的硬地板 |
| 只量化第 3 隐层 1/256 | 76 | 最后隐层分辨率不足 |
| 真实 INT8 隐层 + 浮点末层 | 131 | 末层 FPU **不能**收回已损失的隐层信息，非法点反而更多 |
| 交付 INT8 全网络 | 122 | 末层整数与隐层共同量化，略好于“INT8 隐层 + 浮点末层” |

权重：四层 copied 子块按对称幂次 1/64 量化，最大权误差约 0.0078，无裁剪。权重不是主因。

激活范围（官方网格）：

| 层 | 浮点峰值 | 部署尺度 | 是否削峰 |
|---|---:|---:|---|
| 隐层 1 ReLU | 2.778 | 1/64（范围 ±1.98） | 是 |
| 隐层 2 ReLU | 1.212 | 1/128（范围 ±0.99） | 是 |
| 隐层 3 ReLU | 0.526 | 1/256（范围 ±0.50） | 是 |
| 输出 | T 最大 1.154 | 1/64（范围 ±1.98） | 否，但网格过粗 |

生成代码末层反量化是四通道共用 `* 1.562500e-02f`。教师输出动态范围要求的幂次尺度为 D1=1/128、D0=1/256、D2=1/1024、**T=1/64**。T∈[0.831, 1.154]，1/128 的 int8 范围只有 ±0.992，装不下 T。

因此即使用理想的逐通道 8bit 幂次输出量化去拟合教师，T 仍必须用 1/64，**半个 LSB × 2500 = 19.53 个周期计数**。这已经超过 1 个计数验收线，且与隐层无关。

主瓶颈排序：

1. **统一/幂次 8bit 输出无法同时表示 T≈1.15 并把周期误差压到 1 计数**（硬地板约 20 计数）。
2. **隐层激活削峰 + 过粗尺度**，把误差放大到 122 计数，并在 92.2～92.5 V 产生非法输出。
3. 权重量化误差次要。

## 4. 候选方案

TI NNC 2.1.1 / `tinyml_torchmodelopt` 1.5.0 的 TINPU 默认配置：权重量化 `per_channel_symmetric` + 幂次；**激活 `per_tensor_symmetric` + 幂次**。交付的 PWCONV 生成代码没有四通道不同的输出反量化。在 ONNX 里写逐通道输出尺度，不等于硬件会那样执行。

候选均放在 `tools/c2000_debug/experiments/accuracy_20261030/candidates/`，未写入 `model/generated/npu`。

| 方案 | 官方网格最大 PWM 计数 | 非法点数 | 相对当前 INT8 | 延迟（实机或估计） |
|---|---:|---:|---|---|
| FPU 教师 | 0 | 0 | 基准 | 28.92 μs 实机 |
| 紧凑浮点 | 1 | 0 | 等价教师 | 未单独上板，应接近 FPU |
| 当前 INT8 NPU | 122 | 4 | 基准 NPU | 62.85 μs 实机（含 ISR 计时） |
| A 校准 1 V / 0.1 V / 加密 92.x | 122 | 4 | 三个 ONNX 哈希相同，无改善 | 同当前 NPU |
| A 理想逐通道 8bit 输出（仅数值） | 20 | 0 | 仍被 T 的 1/64 卡住 | 若 NNC 支持也不会快很多 |
| B TINPU QAT 40 epoch，教师蒸馏 | 153 | 30 | 更差，90 V 附近即非法 | 未上板 |
| C NPU 前三层 + FPU 末层 | 131 | 35 | 隐层误差留下，去掉 1/64 网格后平均略降、最坏变差 | 未上板；估计墙钟略低于四层 NPU，CPU 不会低于 FPU |

QAT 训练 MSE 仅从 5.4e-4 降到 4.8e-4，独立 90.05 V 网格同样差，不是“只拟合了校准点”的假精度，而是在当前量化约束下没有学到更好的映射。

混合推理的要点已经用真实 ONNX 隐层验证：**最后一层改 FPU 并不能消除前三层量化误差**。在现有 INT8 隐层上这样做，最坏 PWM 误差和非法点都变差。

## 6. 下一阶段建议

**本轮没有找到满足精度要求的 NPU 方案。** 不得降低“1 个实际 PWM 计数”和输出合法性标准。

若仍要 NPU，唯一还值得做的不是继续 PTQ 校准或在现有 INT8 隐层上接 FPU 末层，而是同时满足下面两条，否则应停止 NPU 闭环尝试、继续用 FPU：

1. **T（以及需要 1 计数精度的通道）不要走 8bit 幂次输出。** 周期计数的 20 个计数地板是表示范围决定的，改校准数据消不掉。可行方向是末层浮点，或把 T 改成更适合 int8 的残差编码并改固件映射——后者会改控制语义，超出本轮范围。
2. **先解决隐层削峰，再谈末层 FPU。** 当前隐层 1/2/3 都在削峰。没有这一步，混合推理会继续输出非法点。

不建议继续投入的方向：更密的 PTQ 校准、在 NNC 2.1.1 上强行做逐通道输出、短 QAT 拟合校准点、为精度测试开功率。

当前具有部署价值的推理路径仍然是 **FPU 原网**：28.9 μs，官方网格 PWM 误差为 0，输出合法。NPU 3c 只证明了“可以跑得更快”，没有证明“可以用于 DAB 控制”。
